# 智能体管理与协作

入口：工作室侧栏 → **我的团队**，页面路径 `/agents`。工作室、团队、生成设置与个人中心共用侧栏，切换页面保留折叠状态；账户菜单只保留个人中心和退出登录。

## 定制团队

每个 AtomForge 账号有独立的智能体库，最多保存 24 位成员和 12 支团队。内置的 Atlas、Milo、Luna、Ollie、Neo、Pip 组成初始默认团队。默认团队可以直接编辑、增删和调整成员顺序，也可以复制；仅默认团队本身不能删除。六位内置伙伴始终保留在智能体库中，从团队移除后仍可随时加入。

「我的团队」支持创建、编辑、复制、删除及切换当前团队。每支团队（包括默认团队）选择 1–12 位伙伴，同一位伙伴可以加入多支团队，同一岗位也可选择多位成员。团队名称、介绍、主题色和成员顺序会一起保存。删除当前自建团队时切回已保存的默认团队阵容，成员仍保留在智能体库中。

成员资料包括名字、职责名称、性格与表达方式、职责与关注点、开场白，以及头像。头像可从六种现有风格中选择，也可上传不超过 1 MB 的 PNG、JPG 或 WebP。后端验证图片并转成 256 × 256 的 PNG，移除原始元数据，不接受外部图片 URL 或 SVG。

「智能体库」和所有团队的成员选择窗口都支持按名字、岗位和专长查找，点击卡片直接编辑资料。各处成员头像以及执行日志中的成员标签共用招呼与介绍浮层，支持鼠标和键盘；历史内容展示当时的资料。新建成员时选择领导、产品、设计、架构、开发或测试岗位。执行流程优先将阶段分给具有对应专长的已选成员；未单独配置的岗位由已选伙伴分担，不会加入未选择的默认人员。同岗的额外成员会参与专业建议，每位成员有独立的会话入口。工程师模式仍按项目原有模式运行，不会因切换团队自动改成团队模式。

编辑窗口的「恢复该岗位默认资料」会填回模板，点击保存后生效。「恢复默认伙伴资料」经页面确认后，仅恢复六位默认伙伴的资料，保留所有自建成员以及各团队已保存的阵容、成员顺序和当前选择，不会把已编辑的默认团队重置成六人组合。自建成员须先从所有团队（包括默认团队）中移除，才可删除。

## 团队领导

工作区默认进入本轮负责协调的成员会话；初始六人阵容中由 Atlas 担任。即使调整后的团队没有领导岗位，也会由选中的伙伴承接协调职责。协调成员接收需求、回答问题；必要时实际调用最多三次专业成员咨询，再汇总给用户。咨询的双方消息会保存，可从成员会话或团队动态展开查看。纯咨询不启动生成；明确要求创建、修改、修复或继续实施时，协调成员把用户原话与整理后的要求交给执行流程。公开发布和部署仍通过对应功能执行。

团队任务先由领导返回结构化阶段计划，包含任务、负责人、交付物与把关岗位。工作看板读取这份实际计划。需求先行，设计与架构的顺序由领导决定，然后开发与独立测试；计划不能删除岗位或绕过独立验收。把关岗位表示计划中的责任分配，只有实际审查和浏览器验证完成才显示验收通过。

专业成员接收具体调度单，完成后向领导交接。构建或独立验收失败时，领导根据真实错误制定修复安排，再交给工程师实施和测试复验；调整记录显示在看板中。依旧最多两次自动修复，通过验证才保存正式版本。

任务执行中发送的修改会先保存到当前任务，在模型调用、确认卡、构建或保存之前的安全节点合并。保留已生成草稿，重新规划并重新验收；等待确认时也能用新反馈替换旧确认事项。保存已经开始时明确提示稍后重试，不谎报已接单。故障重试保留待处理反馈。

## 性格如何生效

性格和职责进入实际模型请求，覆盖团队阶段、代码生成、修复和单独角色讨论；不会套用到生成应用自身的 AI 助手或报告服务。头像和名字同步显示在首页伙伴区、会话、交接记录、确认卡及团队看板。

默认成员各有侧重：

| 成员 | 性格与协作方式 |
| --- | --- |
| Atlas | 沉着、坦诚；承接需求，协调专业意见，明确分工，依据验收结果交付 |
| Milo | 温暖、有条理；倾听分歧，明确目标，补齐交接信息 |
| Luna | 细腻、有想象力；以使用感受解释设计，与开发讨论取舍 |
| Ollie | 沉稳、严谨；拆解复杂问题，说明风险及可行替代方案 |
| Neo | 务实、爽快；回应建议，用实际成果说明进展，主动处理问题 |
| Pip | 耐心、敏锐；给出复现依据，验证修复后才宣布通过 |

模型会接收实际队友名单和真实交接上下文，可输出专门的 `handoff` 留言。交接回应上一位成员的具体产出，说明下一步交给谁；不通过虚构同事发言或无意义闲聊制造协作感。性格偏好不能取消结构化输出、平台权限、用户确认的范围、构建检查或独立验收。

## 持久化与历史

- `studio_agent_settings` 保存成员库、`teams`、`active_team_id`、派生的阶段安排 `active` 和配置版本号。版本号防止过期页面覆盖最新设置。
- 每次任务启动时，将当前团队的完整成员及阶段安排写入任务 payload。执行、确认后继续和失败重试使用这份快照。切换团队、增删成员和修改资料只影响后续新任务。
- 快照保留六个阶段键，并用 `member:<智能体 ID>` 保存完整、有序的真实成员名单。头像和成员会话按真实成员去重；阶段看板按负责人显示，同一成员可以承担多个阶段。同岗成员的会话与历史记录按成员 ID 区分。
- 后续改名、换头像、删除或恢复默认，不改写旧任务与交接记录中的成员身份。直接讨论也保存当次身份。
- V2 之前未保存身份快照的记录使用原有五位默认成员。
- 已有账号配置保留原有成员定制和配置版本；升级前的自定义岗位组合迁移为「我的原团队」并继续使用，同时补入默认团队。旧任务历史不补造领导参与记录。
- 团队设置只在当前账号下读写，不涉及共享其他人的成员库。

正常使用仓库启动脚本时，数据库初始化会自动创建新增表；已有数据库先备份，再做增量升级。直接手工启动后端的环境需先运行 `scripts/init_local.py`，或部署入口对应的 `bootstrap_db.py`。

## 验证

后端智能体测试覆盖团队增删改与切换、成员引用、阶段分配、账号隔离、版本冲突、头像校验、身份快照及成员讨论。前端 `app/frontend/scripts/test-agent-teams.mjs` 覆盖单人团队、同岗成员、完整成员名单、旧配置迁移和历史身份兼容；`test-conversation.mjs` 检查会话分组与工具记录。模型与工作流测试使用临时数据库和模拟模型。
