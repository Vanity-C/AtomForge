# 智能体管理与协作

入口：账户菜单 → **智能体管理**，或生成设置中的管理链接，页面路径 `/agents`。

## 定制团队

每个 AtomForge 账号有独立的智能体库，最多保存 24 位成员。内置的 Atlas、Milo、Luna、Ollie、Neo、Pip 是默认模板，也可以直接编辑。

成员资料包括名字、职责名称、性格与表达方式、职责与关注点、开场白，以及头像。头像可从六种现有风格中选择，也可上传不超过 1 MB 的 PNG、JPG 或 WebP。后端验证图片并转成 256 × 256 的 PNG，移除原始元数据，不接受外部图片 URL 或 SVG。

新建成员时选择领导、产品、设计、架构、开发或测试岗位。当前团队每个岗位安排一位成员；成员库中的其他人可随时替换进团队。工程师模式由领导规划、开发成员实现与自测。

编辑窗口的「恢复该岗位默认资料」会填回模板，点击保存后生效。「恢复默认团队」经页面确认后恢复六位默认伙伴并移除自建成员。未在当前团队中的自建成员可以删除。

## 团队领导

工作区默认进入 Atlas 的对话。领导接收需求、回答问题；必要时实际调用最多三次专业成员咨询，再汇总给用户。咨询的双方消息会保存，可从成员会话或团队动态展开查看。纯咨询不启动生成；明确要求创建、修改、修复或继续实施时，领导把用户原话与整理后的要求交给执行流程。公开发布和部署仍通过对应功能执行。

团队任务先由领导返回结构化阶段计划，包含任务、负责人、交付物与把关岗位。工作看板读取这份实际计划。需求先行，设计与架构的顺序由领导决定，然后开发与独立测试；计划不能删除岗位或绕过独立验收。把关岗位表示计划中的责任分配，只有实际审查和浏览器验证完成才显示验收通过。

专业成员接收具体调度单，完成后向领导交接。构建或独立验收失败时，领导根据真实错误制定修复安排，再交给工程师实施和测试复验；调整记录显示在看板中。依旧最多两次自动修复，通过验证才保存正式版本。

任务执行中发送的修改会先保存到当前任务，在模型调用、确认卡、构建或保存之前的安全节点合并。保留已生成草稿，重新规划并重新验收；等待确认时也能用新反馈替换旧确认事项。保存已经开始时明确提示稍后重试，不谎报已接单。故障重试保留待处理反馈。

## 性格如何生效

性格和职责进入实际模型请求，覆盖团队阶段、代码生成、修复和单独角色讨论；不会套用到生成应用自身的 AI 助手或报告服务。头像和名字同步显示在首页伙伴区、会话、交接记录、确认卡及团队看板。

默认成员各有侧重：

| 成员 | 性格与协作方式 |
| --- | --- |
| Atlas | 沉着、坦诚；承接需求，协调专业意见，明确分工，依据验收结果交付 |
| Milo | 温暖、有条理；倾听分歧，明确目标，补齐交接信息 |
| Luna | 细腻、有想象力；以使用感受解释设计，与开发讨论取舍 |
| Ollie | 沉稳、严谨；拆解复杂问题，说明风险及可行替代方案 |
| Neo | 务实、爽快；回应建议，用实际成果说明进展，主动处理问题 |
| Pip | 耐心、敏锐；给出复现依据，验证修复后才宣布通过 |

模型会接收实际队友名单和真实交接上下文，可输出专门的 `handoff` 留言。交接回应上一位成员的具体产出，说明下一步交给谁；不通过虚构同事发言或无意义闲聊制造协作感。性格偏好不能取消结构化输出、平台权限、用户确认的范围、构建检查或独立验收。

## 持久化与历史

- `studio_agent_settings` 保存账号配置，版本号防止过期页面覆盖最新设置。
- 每次任务启动时，将当前团队资料写入任务 payload。执行、确认后继续和失败重试使用这份快照。
- 后续改名、换头像、删除或恢复默认，不改写旧任务与交接记录中的成员身份。直接讨论也保存当次身份。
- V2 之前未保存身份快照的记录使用原有五位默认成员。
- 已有账号配置自动补入默认领导，保留原有成员定制和配置版本；旧任务历史不补造领导参与记录。
- 团队设置只在当前账号下读写，不涉及共享其他人的成员库。

正常使用仓库启动脚本时，数据库初始化会自动创建新增表；已有数据库先备份，再做增量升级。直接手工启动后端的环境需先运行 `scripts/init_local.py`，或部署入口对应的 `bootstrap_db.py`。

## 验证

后端新增测试 `app/backend/tests/test_agent_profiles.py` 覆盖保存、创建与岗位安排、默认恢复、账号隔离、并发版本冲突、头像校验、任务与历史身份快照、模型指令及 GPT 角色讨论。

浏览器验收使用隔离的模拟账号数据，覆盖创建、图片选择、内置头像、安排成员、刷新恢复、首页姓名同步、编辑、单人恢复、整队恢复及 390px 移动布局。现有模型调用与工作流测试继续使用临时数据库和模拟模型。
