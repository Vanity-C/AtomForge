# v0.3.9：集中验收与一次反馈

## 行为变化

测试工程师先通读当前源码并核对已确认的验收要求，汇总本轮能够确认的缺陷。开发自测、源码审查、独立浏览器场景中的问题合并后一次交给应用工程师；工程师按完整清单修复后再交回验收。

QA 支持最多 6 个独立场景，总计最多 48 步。每个场景使用全新隔离浏览器及空存储，并自带前置步骤。一个场景失败时停止该场景中依赖失败状态的后续操作，其他独立场景继续运行；源码审查发现缺陷后也会执行可运行的场景。

编译或页面挂载阻塞时继续源码审查，未运行场景明确记录为“阻塞 · 未执行”。测试协议/前置条件错误先由 QA 整理和验证，避免把无效测试报告交给工程师改业务代码。只在源码审查、开发自测和所有必需场景真正通过后保存版本。

看板新增集中验收报告，显示每个场景状态、真实日志、完整问题清单与验证限制。旧版单场景测试和已有任务记录继续兼容，不需要数据迁移。当前 runner 接口保持不变，后端按场景顺序调用现有隔离执行器。

此调整旨在减少可提前发现问题的往返；没有保证一次找出所有缺陷，也没有通过降低验收标准或减少修复次数来掩盖问题。模型漏检、修复引入的新问题、前置阻塞及平台无法验证的外部条件仍可能要求后续复验。
