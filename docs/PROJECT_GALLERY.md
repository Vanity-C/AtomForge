# 项目画廊与预览封面

入口：工作室侧栏 → 我的项目。项目以 16:10 预览卡片展示，支持搜索、排序、收藏、重命名和删除。收藏保存在当前浏览器，按 AtomForge 账号区分。

工作室、团队、生成设置和个人中心的侧栏共用会话内项目列表，切换路由复用已加载的数据（包括空列表）与在途请求。缓存保留 5 分钟，过期后下次进入页面静默更新；手动刷新立即更新且保留现有内容。创建、重命名、删除、保存版本、回滚和分享操作会同步更新缓存，工作台读取项目也会同步最新版本。退出或更换账号后清空，旧会话响应无法回写。缓存与身份竞态验证：在 `app/frontend` 运行 `node --test scripts/test-project-collection.mjs scripts/test-auth-session.mjs`。

封面来自项目实际代码的初始页面渲染。新构建在交互验收前截图；历史构建按需补图，只有源码的项目在卡片进入可见区域后构建并截图。没有源码的项目显示待创作状态，失败时可以重试，不使用虚构预览。生成封面不调用模型。

后端 `/api/v1/af/projects/{id}/thumbnail` 按成员权限读取，慢任务结束后再次核对权限与项目版本。JPEG 封面保存在当前 `studio_artifacts.content` 中；不新增数据库表。请求按项目版本合并，前端可见卡片串行加载，截图与构建、runner 就绪检测共享浏览器互斥。HTTP 和 WebSocket 外连均受截图沙箱限制。

部署此功能时须同时更新 app 和 runner，确保 runner 包含 `/thumbnail` 与初始封面捕获能力。仅更新前端或 app 无法为旧项目补图。部署仍使用 [现有部署流程](DEPLOYMENT.md)，升级前备份数据。

验证：`app/backend/tests/test_project_thumbnails.py` 覆盖权限、历史项目补图、源码补构建、版本更新、失败缓存和等待期间撤销成员权限；`app/runner/test.mjs` 验证真实截图、交互前封面与外连隔离。
