# 测试计划步数配置

默认最多 **1000 步**。团队任务的「领导战略看板 → 测试步骤上限」可设置为 2–10000 的整数，不能低于「独立测试最少步骤」。填写调整原因后保存；与现有策略一样，需要任务所有者操作，并校验策略版本。

上限是容量，不要求生成或执行满额测试。一个独立验收报告的所有场景共享总额度，每个场景至少两步、以结果断言结束。每个场景在独立浏览器环境内连续执行，保留步骤间的状态，不拆散、不截断测试。开发自测同样遵循本轮上限。

每轮开始时固定步数策略，生成、报告纠正、诊断和执行使用同一份配置。保存调整后，在下一轮计划或恢复验收时使用新值；已开始执行的计划不在中途改变上限。旧任务未记录该字段时自动使用部署默认值，原测试步骤和历史报告保留。

部署级默认值使用 `ATOMFORGE_MAX_TEST_STEPS`。Docker Compose 中可在项目根目录 `.env` 中设置 `ATOMFORGE_MAX_TEST_STEPS=1500`，或在启动 Compose 的进程环境中设置；Compose 会向 app 与 runner 传入同一数值。`.env.docker` 不是此 Compose 插值配置的入口。直接运行服务时，两个进程都应设置同一个变量。修改部署默认值后需重启相关服务，已有任务显式保存的策略优先。

测试浏览器预算按实际步骤数计算：`max(60, 30 + 3 × 步数)` 秒，每步通常最多等待 2.5 秒。执行器任务预算额外增加 30 秒，后端读取执行结果额外增加 60 秒；健康检查遵循当前任务预算。请求断开时关闭该请求的浏览器，避免长测试占用资源。测试计划最多 10000 步，请求体最多 10 MB。

超出配置上限或不符合动作协议时，保留计划并交测试工程师纠正；不会截断步骤或将未执行内容标记为通过。配置扩容只解除数量与固定总时限造成的阻塞，真实断言失败仍会如实报告。
