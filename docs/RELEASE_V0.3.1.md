# v0.3.1：团队恢复与发布状态修复

本次补丁解决团队交接文案过长中断任务、修复预算偏低、恢复入口难以发现及源码发布误显示公网部署进度的问题。

- 移除 `handoff` 的 400 字硬校验，完整内容保存在文档并传给下游；界面仅缩短消息预览，不截断需求或代码。
- 团队默认最多 30 轮自动修复重测，另有首次验证。提前通过即交付；耗尽仍未通过时保留草稿与诊断，不将失败标记为成功。
- 继续旧任务时，未调整过的旧默认 2 轮预算升级为 30 轮；已记录的策略调整和新版明确设置的较低预算保留。
- 工作看板顶部将失败状态与“继续任务／继续验收”并排显示，滚动时保持可见；诊断详情折叠，恢复中禁止重复提交。
- GitHub／Gitee 源码发布与 Netlify 部署分别显示加载状态；其他操作等待时给出原因，不再误显示正在部署。

模型连接、账号额度、外部服务和真实应用缺陷仍可能影响任务完成；增加修复轮次不代表保证生成成功。实际构建及独立测试门禁继续保留。

本轮沿用 v0.3.0 的 runner；生产更新前备份数据库与签名密钥，保留上一版本镜像用于回退。

## 验证

- 完整后端回归 188 项、前端逻辑回归 67 项通过；TypeScript 与 ESLint 通过。
- 隔离浏览器验证了桌面／手机恢复入口、加载／失败／成功反馈，以及 GitHub／Gitee／Netlify 提交、重试和重新打开面板时的独立进度显示。
- Linux amd64 生产镜像构建通过；未新增真实第三方发布或生产模型生成测试。
