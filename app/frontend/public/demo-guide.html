产品目标

AtomForge 将“描述一个想法 → 智能体生成代码 → 看见并操作应用 → 继续修改 → 发布”连成一条完整流程。目标受众是希望快速验证想法的个人开发者，第一版重点是可体验、可追溯、可继续开发，而不是复刻 Atoms 的全部商业能力。

五分钟体验

  1. 打开首页，注册自己的用户名、邮箱和密码。支持用户名或邮箱登录。
  2. 进入工作台，选择“团队模式”，输入：“做一个看板式待办应用，支持创建任务、切换状态和标签筛选。”
  3. 查看 Milo（产品）、Luna（设计）、Ollie（架构）、Neo（开发）、Pip（测试）的交接。常规决定由团队处理，必要事项才出现带选项的确认卡。
  4. 在右侧切换“预览 / 文件 / 工作看板”。展开工具卡可查看实际执行输入、结果与耗时；生成草稿与已保存版本明确区分。
  5. 在应用内新增任务、切换状态，再刷新验证数据保留。继续发送“小改动”需求，例如增加标签删除和二次确认。
  6. 打开“云服务与发布”，发布通过验证的应用，复制独立访问链接；也可分享只读源码、导出 ZIP 或回滚版本。

首次生成需要调用真实模型和运行浏览器检查，耗时随需求与服务状态变化。等待时可查看当前阶段；上翻历史不会被新消息强制拉回底部。生成失败会保留进度与已有版本，不会假装完成。

实现思路与关键取舍

系统结构

浏览器：React / TypeScript / Vite
             │ HTTPS
           Caddy
             │
FastAPI：账号、项目、任务、版本、模型调用、发布
   │                 │                    │
SQLite 数据卷      DeepSeek API       内部 runner 容器
                                      esbuild + Chromium
  • 真实模型协作：五个角色使用各自的指令、交接结构与职责，通过同一选定模型按依赖顺序协作。不是五个独立模型供应商，也不是并行模拟聊天。
  • 先验证再保存：模型产出增量源码，runner 编译并检查真实页面，团队还须经过独立 QA；通过后保存代码、版本和构建产物。验收失败保留草稿。
  • 控制修改范围：已有文件优先使用唯一精确匹配的局部补丁，避免小改动重写整个文件造成截断。补丁校验失败时整套不应用。
  • 把状态交给服务端：任务、交接、确认、用户选择和用量保存在 SQLite。关闭页面不取消任务；刷新读取真实状态。确认倒计时由服务端执行。
  • 单机可复现：SQLite 与 Compose 降低部署成本和运维复杂度，适合个人 Demo；代价是单 worker、有限并发，尚非分布式服务。
  • 受控运行环境：只允许固定 React 依赖，不执行任意安装脚本；runner 无模型密钥和 Docker socket，浏览器测试拦截外部网络。代价是暂不支持任意技术栈与完整终端。
  • 诚实呈现进度：展示工作说明、工具输入、结果与总结，不展示或伪造模型内部思维链。恢复中的问题不会被当成最终失败；诊断可展开查看。

AI 工具如何参与

基于已有 React/FastAPI 项目原型，借助 Codex 持续完成代码理解、功能迭代、数据库兼容、Docker 配置、回归测试、浏览器实测和发布准备。产品运行时使用服务端 DeepSeek 模型调用。没有把静态页面包装为“智能体已开发”，也没有将外部服务替身测试写成真实账号已接通。

第一版不包含：任意 npm 包/服务端代码执行、每项目独立虚拟机、多机任务调度、多人实时合并、GitHub 双向同步、支付订阅/退款、自动广告投放。云服务在隔离浏览器中用测试替身，不把它当成真实支付或外部网络验收。

验证与工程质量

自动化检查覆盖账号与数据隔离、角色交接、必要确认、草稿恢复、精确补丁、模型格式与截断恢复、有限重试、版本冲突及真实浏览器执行。前端检查包括 TypeScript、lint、对话分组与状态逻辑；runner 使用 Chromium 实际编译和操作生成应用。

真实项目回归案例：同一“删除标签”需求，旧流程三次完整文件输出均到 12,000 token 截断；局部补丁实现后，一次工程师调用用 1,051 个输出 token 完成修改，通过独立验收并保存版本。这个数据仅说明该案例的改进，不代表所有请求的性能或费用保证。

浏览器验证了：标签删除取消/确认、任务标签同步移除、选中筛选清理、刷新持久化，以及临时测试数据清理。平台保留了用户原有数据。

后续投入优先级

  1. P0：稳定性与评审可用性。真实任务回归集、错误分类、可观测性、备份恢复演练、持久队列与服务重启续跑。先让核心流程稳定，再扩张功能。
  2. P1：运行隔离与协作开发。每项目隔离环境、更细的工具权限、GitHub 导入/双向同步和冲突处理。提升复杂项目可扩展性。
  3. P2：完整外部集成。支付、研究服务的真实端到端联调，模板复用、移动端体验与多人实时协作。依据真实使用反馈排序。
